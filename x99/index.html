The X99 Build

One secondhand Huananzhi X99-BD4 board turned into a roughly $200 inference server that I keep extending: soldering its PCIe lanes, flashing its BIOS, waking it over the network, unlocking the mining GPUs, and running two NVIDIA cards on two different drivers at once, pooled for one model.

The second GPU slot now holds an AMD Radeon VII on ROCm, next to the unlocked CMP 40HX. The Tesla V100 goes back into that slot when I want the pooled VFIO setup, and the Radeon comes out.

Rebuilding it

The whole box is described in X99-Recreation, an Ansible playbook that rebuilds it from a fresh Ubuntu install:

  • base, tailscale: packages, hostname, user groups, Tailscale SSH.
  • nvidia_cmp40hx: installs the 610.57.04 userspace, pins and holds the driver packages, builds the cmpunlocker modules, and installs the boot units below.
  • amdgpu_power: the Radeon VII power cap.
  • ollama, cuda_toolkit, plus optional mistralrs and benchmarks roles.

What happens at boot

  1. The patched NVIDIA modules load and try their own Gen2 retrain, which fails on this board’s root port.
  2. cmp40hx-gen2-retrain reprobes the driver so the card advertises Gen2, then retrains the link from the root port: 2.5 → 5 GT/s. It checks the PCI ID first, so it won’t touch a different card if the slots change.
  3. cap-cmp40hx locks the CMP’s idle clock to 300 MHz (cmp40hx-uncap releases it for inference).
  4. amdgpu-power-cap finds the Radeon VII by PCI ID and sets its cap to 200 W.

The unlock is volatile and the patched modules are built per kernel, so a kernel hook rebuilds cmpunlocker for every new kernel before it’s booted.
